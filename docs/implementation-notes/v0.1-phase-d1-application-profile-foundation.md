# V0.1 Phase D.1 — ApplicationProfile Foundation

**Status:** Complete

## Atomic task

Define the first V0.1 domain boundary: the application context that later authentication work must
resolve before it can make method, registration, policy, or navigation decisions. Do not add EF
Core, a repository, application lookup, an authentication route, or any of the other Phase D
entities.

## Code boundary

`AuthNexus.Modules.Applications` owns `ApplicationProfile`, `RedirectUri`, and the application
type, audience, and mode enums. `AuthNexus.Domain` owns `ApplicationId` and `TenantId` because those
identifiers will cross later transaction, session, audit, and notification boundaries.

The resulting production dependency change is deliberately one-way:

```text
AuthNexus.Modules.Applications -> AuthNexus.Domain
```

No module-to-module reference was added. The architecture suite now declares this single inward
dependency and continues to reject every undeclared production reference.

## Profile state

A constructed profile contains:

- non-empty application identity and an optional non-empty tenant identity;
- a declared application type, audience, and registration mode;
- a trimmed display name and canonical default locale;
- a required authentication-policy reference;
- an optional registration-schema reference;
- one or more copied, canonical, duplicate-free web redirect destinations.

The profile is immutable after construction. It exposes `AllowsRedirectTo` for exact membership
against its canonical allowlist; it does not accept raw request input or perform application
lookup.

## Redirect rules

`RedirectUri.Create` accepts absolute HTTPS destinations and HTTP only when `Uri.IsLoopback` is
true. It rejects relative values, absent or wildcard hosts, user information, fragments,
backslashes, external HTTP, and non-web schemes. This establishes a safe web redirect value without
prematurely designing native custom schemes or the future HTTP redirect-validation pipeline.

## Acceptance evidence

- `dotnet restore AuthNexus.sln` restored 19 solution projects.
- `dotnet build AuthNexus.sln --configuration Release --no-restore` completed with zero warnings
  and zero errors.
- `AuthNexus.Modules.Applications.Tests` passed all 34 local tests.
- The test suite covers valid tenant and tenantless profiles, empty/default identifiers, enum
  fall-through, required and optional text, locale canonicalization, safe and unsafe URI forms,
  duplicate canonical redirects, defensive collection copying, and allowlist membership.
- Windows Application Control blocked a copied Recovery module DLL when the architecture test host
  loaded it. The policy was left enabled; the hosted Linux backend job remains the acceptance
  environment for both architecture rules.

## Deferred

D.1 does not persist, seed, retrieve, cache, serialize, or administratively edit a profile. It does
not evaluate the policy or registration-schema references. Branding, supported locales,
authentication-method configuration, organization discovery, native return links, and post-login
destinations remain outside this slice. D.2 begins the `UserAccount` identity root; Phase E begins
persistence; later phases own profile resolution and authentication HTTP behavior.
