# V0.1 Phase C — Backend Module Boundaries

**Status:** Complete

## Atomic task

Replace the ownership-only module map with compile-time boundaries and make project-reference
drift fail the normal backend test command. Do not introduce entities, persistence, provider code,
dependency-injection registration, or HTTP behavior.

## Boundary decision

The eleven required product modules are separate `AuthNexus.Modules.<Module>` class libraries.
This is more explicit than namespaces inside one assembly: the C# compiler now prevents a module
from using another module unless a project reference is deliberately added.

`AuthNexus.Application` references every module and remains the only production boundary intended
to coordinate work across them. Module projects have no direct references. `AuthNexus.Contracts`
and `AuthNexus.Domain` also remain dependency-free. Infrastructure depends inward on Application,
Contracts, and Domain; the API composes Application, Contracts, and Infrastructure.

Each module contains only a `ModuleAssemblyMarker`. The marker confirms the assembly and namespace
exist; it does not register services or claim that the module's future responsibilities are
implemented.

## Automated enforcement

`tests/architecture/AuthNexus.Architecture.Tests` contains two executable rules:

- the compiled module-marker assemblies must exactly match the eleven-module catalog, and every
  marker namespace must match its assembly name;
- the production projects discovered under `src/backend` plus `apps/api` must exactly match the
  declared direct-reference graph.

The second rule rejects undeclared backend projects as well as forbidden or missing references.
An intentional architecture change therefore requires a visible update to the expected graph.
The test uses only the existing xUnit toolchain and the .NET XML APIs; no architecture-analysis
package was added.

## Acceptance

- `dotnet restore AuthNexus.sln` restores all 18 solution projects.
- `dotnet build AuthNexus.sln --configuration Release --no-restore` compiles the eleven module
  assemblies and the architecture suite with warnings treated as errors.
- `dotnet test AuthNexus.sln --configuration Release --no-build` runs the product-contract test
  and both architecture rules in source CI.
