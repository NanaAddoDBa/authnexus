# V0.1 Phase B — Local Runtime and Infrastructure

**Status:** Complete

## Atomic task

Add the dependency stack needed by later V0.1 implementation work: PostgreSQL, Redis, Mailpit,
Docker Compose, and service health checks. Do not connect the API, add EF Core, create migrations,
or invent provider interfaces in this task.

## Files changed

- `compose.yaml` pins PostgreSQL 16.10, Redis 7.4.5, and Mailpit 1.27.4.
- `.env.example` contains matching local ports, credentials, and future connection-string inputs.
- `infra/docker/verify-local-stack.ps1` checks container health and actual dependency access.
- `.github/workflows/validate.yml` adds a local-runtime job and makes the mirror dispatch wait for
  it.
- `README.md`, `docs/local-development.md`, `docs/releases/v0.1.md`, and the infra readmes describe
  the local runtime, its reset behavior, and the code that is still missing.

## Runtime behavior

- PostgreSQL listens on `127.0.0.1:5432`, initializes database/user `authnexus`, and stores data in
  `postgres-data`.
- Redis listens on `127.0.0.1:6379`, requires the local password, enables append-only persistence,
  and stores data in `redis-data`.
- Mailpit accepts SMTP on `127.0.0.1:1025`, serves its UI/API on `127.0.0.1:8025`, and stores
  messages in `mailpit-data`.
- Ordinary `docker compose down` retains data. `docker compose down --volumes` deletes it.

## Security notes

The checked-in credentials are deliberately recognizable local defaults, not secrets. All host
ports bind to loopback and containers use `no-new-privileges`. This does not provide TLS, secret
management, backup, production network policy, or a hardened deployment configuration.

## Local evidence

Accepted on Docker Engine 29.7.2 / Compose 5.4.0:

- `docker compose config --quiet` passed.
- `docker compose up --detach --wait --wait-timeout 120` brought all three services to `healthy`.
- PostgreSQL returned `authnexus|authnexus` for the current database/user query.
- Authenticated Redis returned `PONG`.
- Mailpit `/api/v1/info` reported version `v1.27.4` and `/mailpit readyz` passed.
- `infra/docker/verify-local-stack.ps1` passed.
- A test message sent to `localhost:1025` appeared in Mailpit, and the message count remained `1`
  after `docker compose down` followed by a fresh `up`, confirming volume reuse.

The source workflow repeats the Compose model, startup, and verification checks on every push and
pull request. Downstream mirror dispatch is blocked unless that job, frontend, and backend all pass.

## Deferred

outside this atomic task.
