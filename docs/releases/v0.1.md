## V0.1 exit gate

The eventual release must start the web, API, and dependency stack; resolve an application
profile; execute an authentication transaction lifecycle; issue and revoke a server-managed
session; enforce redirect and policy boundaries; persist audit/outbox records; and pass its defined
tests. Phases A through C supply the repository, local dependencies, and compile-time boundaries;
they satisfy none of the product-behavior items by themselves. D.1 defines valid application
configuration, D.2 defines valid account-state transitions, D.3 defines the central transaction's
purpose, lifetime, and legal state graph, D.4 defines session lifetime, verifier rotation,
revocation, and expiry invariants, and D.5 defines immutable security-event context and metadata.
D.6 defines the protected notification envelope and its due, retry, delivery, and
permanent-failure rules. None of those models is resolved, persisted, orchestrated, or invoked by
a request.
