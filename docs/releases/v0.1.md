## V0.1 exit gate

The eventual release must start the web, API, and dependency stack; resolve an application
profile; execute an authentication transaction lifecycle; issue and revoke a server-managed
session; enforce redirect and policy boundaries; persist audit/outbox records; and pass its defined
tests. Phases A through C supply the repository, local dependencies, and compile-time boundaries;
they satisfy none of the product-behavior items by themselves. D.1 defines valid application
configuration, D.2 defines valid account-state transitions, D.3 defines the central transaction's
purpose, lifetime, and legal state graph, and D.4 defines session lifetime, verifier rotation,
revocation, and expiry invariants. None of those models is resolved,
persisted, orchestrated, or invoked by a request.

## Next atomic step

D.5 should introduce the immutable `SecurityEvent` record, the fixed 37-event catalogue, a
declared result vocabulary, optional actor/target/application/session context, required
correlation, and bounded defensive metadata. It must not add event storage, queries, runtime
emitters, a redaction pipeline, or an audit endpoint before Phase E/I defines those contracts.
